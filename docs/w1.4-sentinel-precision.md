# W1.4 sentinel precision corrections

## Root causes

- **Borg:** the 120-minute agreement was sound. During an active oneshot,
  `ExecMainExitTimestamp` is blank, so the collector converted a healthy running
  backup into an invalid age. The collector now uses the recent start timestamp
  while active and the successful exit timestamp while inactive.
- **Doctor:** daily synthesis invoked the vault-local skill copy without an
  explicit app repository, temporarily writing a hard-fail report. The canonical
  automation prompt now mandates the app checkout, explicit repo, graph runtime,
  and output path.
- **Power Nap:** Tailscale `Online` is not evidence of an interactive wake. The
  Mac probe now records HID idle state. Mac job contracts apply only to a fresh,
  interactive snapshot; the reporter itself remains expected during online
  daytime hours.
- **Project store:** rsync completed, but the post-sync rebuild sourced an
  unquoted semicolon-bearing path-alias value and exited 127. The environment
  value is quoted and the sync script no longer sources the dashboard environment
  for a build that does not need it.

## Alert policy

Before this change, every first failed sample and every recovery sent an ALERT.
A healthy Borg run produced four open/recovered pairs in 36 hours. Now cards still
open at the first failed sample, but notification waits until the failure remains
open for 30 minutes. A recovery ALERT is sent only if the opening failure was
notified. The independent sentinel-process dead-man remains immediate.

The W1.3 quiet-night clock restarts after deployment. Two overnight observations
and 48 hours without Borg/doctor flap-pair alerts remain receipt gates.
